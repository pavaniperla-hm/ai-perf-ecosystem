Root Cause Analysis

Root Cause

All six latency thresholds breached (p95 ranging from 127ms to 191ms against a 30ms limit). The regression is caused by two compounding factors:

1. Threshold miscalibration for AKS network: The regression-test.js thresholds (p(95)<30ms) were intentionally set tight to always trigger a FAIL on AKS. Baseline AKS latency measured in March 2026 is ~42–56ms at p95 under 10 VUs — nearly 2× the threshold before any load is applied. This is expected network overhead from the Azure North Europe region to the test runner, not a service regression.

2. Dynatrace agent cold-start overhead: user-service and order-service pods were restarted immediately before this test run to inject the OneAgent via LD_PRELOAD. The Dynatrace agent requires a 60–90s initialisation period during which it adds ~80–130ms additional JVM/library overhead per request. This pushed p95 from the typical ~52ms up to 181ms for this specific run. Subsequent runs should return to the ~50ms baseline once agents are warmed up.

Recommended: p(95)<100ms for all transaction thresholds (3× the observed steady-state baseline of ~52ms p95 at 10 VUs). This will ensure genuine regressions are caught while eliminating expected network overhead false positives.
