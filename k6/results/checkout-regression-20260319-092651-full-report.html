7 — Root Cause Analysis

Primary Finding — Threshold Calibration vs Network Reality
All 5 per-transaction thresholds are intentionally tight (p95 < 30ms, p95 < 60ms for orders). AKS round-trip to northeurope ingress adds ~45-55ms baseline network latency. Actual p95 values (64–80ms) represent consistent, healthy response times — not a service degradation. The regression signal is by design.
Secondary Finding — Container Restarts on All Three App Services
Dynatrace reports an open "Container restarts" infrastructure problem. All three app service pods (user-service, product-service, order-service) each show 2 restarts. Pod restarts cause brief connection pool draining and cold-start overhead, which can push individual requests into the p95 tail. Investigate restart root cause — likely OOMKilled or liveness probe misconfiguration.
Latency Pattern
All transactions are uniformly slow (63–80ms, within 26% of each other). This uniform pattern suggests a shared bottleneck rather than a single slow endpoint. Leading candidates: (1) AKS ingress-nginx keepalive / HTTP/2 configuration, (2) PostgreSQL connection pool saturation under concurrent load, (3) shared network path latency from k6 runner to northeurope ingress.
Loki: 0 application-level errors or warnings logged during the test window (09:28:23 – 09:30:39 UTC). All 2,972 k6 checks passed. HTTP 0% error rate. The performance regression is purely latency-driven — no functional failures.
